## Task 3: Make persisted cart state hydration-safe

**Objective:** Preserve cart persistence without rendering different initial markup on the server and client.

**Files:**
- Modify: `src/lib/cart-context.tsx:50-72`
- Modify: `scripts/test-e2e.mjs` or add a focused Playwright check for seeded `localStorage`

**Steps:**
1. Initialize `items` to an empty array for the first render in both server and browser environments.
2. Add a one-time client `useEffect` that reads `CART_STORAGE_KEY`, validates that the parsed value is an array of cart-like items, and then sets the items.
3. Prevent the persistence effect from overwriting existing storage with the initial empty array before the load effect completes. A `hasLoadedStorage` ref/state gate is appropriate.
4. Keep malformed or non-array storage safe by falling back to an empty cart and replacing invalid storage only after initialization completes.
5. Add a browser assertion that seeds one cart item before navigation, verifies the cart badge, and records zero hydration errors.
6. Run the type check, build, and focused browser test.

**Acceptance:** A seeded persisted cart appears after hydration with no React hydration warning/error, and a fresh browser still starts with an empty cart.

**Tradeoff:** The cart badge may appear one render later while storage loads; this is preferable to invalid server/client markup. If immediate display is required, use a `useSyncExternalStore`-style client store with a stable server snapshot instead.
